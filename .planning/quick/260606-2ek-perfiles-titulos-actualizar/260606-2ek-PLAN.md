<objective>
Make "update the ACTIVE profile (titles included)" a reliable, obvious, one-click action in
ProfilesMenu. Today the only way to re-save a profile is to manually re-type its exact name into the
save-as field so the button flips to "Actualizar" — easy to skip or mistype. The result: profiles
never reliably diverge in their titles (e.g. `general.json` and `rojo.json` are byte-identical), so
switching profiles "doesn't change the titles."

This is NOT a save/switch code bug — the orchestrator traced the live flow and confirmed APPLY,
SAVE, and getCurrentConfig() all work correctly. The fix is pure ProfilesMenu UX: surface a primary
"Actualizar «{activeName}»" affordance that re-saves getCurrentConfig() to the active profile in one
click without re-typing.

Purpose: Each profile carries its OWN titles (user decision: "Cada perfil = sus títulos"); updating
the active profile must be trivial so titles actually persist per-profile.
Output: Updated ProfilesMenu.tsx with the one-click update affordance + tests. No backend changes,
no title/state-architecture rewrite, no renderer sync.
</objective>
